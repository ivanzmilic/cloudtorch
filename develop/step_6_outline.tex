\section{Objective}

Turn the validated stack --- today the notebook \co{step\_5\_reg\_test.ipynb} --- into one configurable, resumable script that fits the \emph{full} $(t,y,x,\lambda)$ cube on GPU. \textbf{No new physics or model changes:} \co{ParameterField}, \co{composite\_synth}, \co{chi2\_per\_pixel} and \co{regularization\_loss} are reused verbatim; only the driver (data\,$\to$\,basis\,$\to$\,field\,$\to$\,train\,$\to$\,save) is new. Success: a no-arg run reproduces the step-5 notebook, and the full-field run is reached by editing \emph{config alone}. This closes \co{instructions.md}.

%% ------------------------------------------------
\section{Notebook $\to$ script}

A thin driver (\co{fit\_cube.py}) mirrors the notebook cells as functions: \co{load\_data} (auto-detect path, border and $\lambda$ crop, normalise by $I_{qs}$), \co{build\_basis} (\co{fit\_background\_basis}, or load a persisted basis), \co{build\_field} (\co{ParameterField} $+$ the field-average \co{bkg\_bias}), \co{train} (cosine-annealed Adam; loss $=\chi^2+$\co{regularization\_loss}; grad-clip; optional minibatch), \co{save\_outputs}. The diagnostic/plot cells (emission check, maps, spectra, residuals) become an optional \co{-{}-report} that writes the figures $+$ the $\chi^2$/RMS/emission summary to the out-dir, \emph{off} the training hot path. The per-pixel core (steps 1--5) is untouched.

%% ------------------------------------------------
\section{Config \& CLI}

One grouped config object (dataclass or dict) exposing every top-of-notebook knob: \emph{data} (path list, border \co{YS/XS}, \co{LAM}, \co{N\_BASIS}, \co{K}, frames \co{T0/N\_T} or \emph{all}, \co{CROP} or \emph{full}); \emph{field} (\co{N\_FREQ}, \co{SIGMA\_XY}, \co{SIGMA\_T}, \co{WIDTH}, \co{DEPTH}, \co{S\_MAX}, \co{DV\_FLOOR}, \co{seed}); \emph{train} (\co{N\_ITERS}, \co{LR}, \co{GRAD\_CLIP}, \co{BATCH}, \co{device}); and the grouped \co{REG} dict verbatim. Loaded from a JSON/YAML file, with a few \co{argparse} overrides (\co{-{}-config}, \co{-{}-resume}, \co{-{}-out}, \co{-{}-device}, \co{-{}-crop}, \co{-{}-n-t}) for quick scans. The step-5 values \emph{are} the default config, so weight/scale scans are just re-launches with a different file.

%% ------------------------------------------------
\section{Full-cube coordinates \& scale transfer}

\co{grid\_coords} normalises \emph{each} axis to $[-1,1]$ over its own extent, so \co{SIGMA\_XY}/\co{SIGMA\_T} and the smoothness weights $w^{xy},w^{t}$ live in \emph{normalised} units --- their physical meaning (cycles per pixel; smoothing length) drifts with crop and frame count. Enlarging the config naively would silently re-scale the step-4/5 tuning. \textbf{Fix:} normalise to a \emph{fixed physical scale} --- $1$ unit $=$ \co{REF\_XY} pixels / \co{REF\_T} frames (config-set), centred on the cube --- \emph{not} to the per-domain $[-1,1]$. Choose \co{REF} so the $40\times40\times4$ tuning crop reproduces today's $[-1,1]$; then the tuned $\sigma$ and weights transfer to the full field unchanged (it merely spans a wider coordinate range at the same per-pixel scale). This is a small addition to \co{grid\_coords} (a physical-scale option); the fallback, if no code change is wanted, is to rescale $\sigma\!\propto\!n$ and $w\!\propto\!1/n^2$ by hand per run. Because every loss term is a per-pixel \emph{mean}, the \co{REG} weights are invariant to \co{BATCH} and pixel-count --- only this normalisation needs care.

%% ------------------------------------------------
\section{Checkpointing, resume \& outputs}

Periodic $+$ final checkpoints hold \co{field.state\_dict}, optimiser, scheduler, iteration, and the RNG states (torch/cuda --- for reproducible minibatching), plus the config and the PCA basis (\co{pca.save}), so a checkpoint is self-contained. \co{-{}-resume} restores all and continues the cosine schedule. Final output: evaluate the field over the full grid under \co{no\_grad}, reshape to $(N_t,N_y,N_x,\cdot)$, and save an \co{.npz} of the background coeffs \co{c}\,$(\cdot,6)$ and \co{p\_cloud}\,$(\cdot,10)$ (incl.\ the frozen \co{loga}) with metadata (\co{wav}, \co{LAM}, $I_{qs}$, config); optional FITS via \co{utils.writefits}. Determinism via the config seeds; the \co{-{}-report} block re-uses the notebook's diagnostics for QC.
